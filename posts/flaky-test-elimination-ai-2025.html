How to Implement Flaky Test Elimination with AI in 2025

Flaky tests are the silent productivity killers lurking in your CI/CD pipeline. One minute they pass, the next they fail—with no code changes in between. In 2025, AI in Software Testing and Security has matured to the point where eliminating these unreliable tests is no longer a manual guessing game. This guide walks you through implementing a robust, AI-powered flaky test elimination system that actually works.

Why This Matters

Flaky tests cost engineering teams an estimated 15-25% of their CI/CD time in wasted builds, false alarms, and debugging sessions that lead nowhere. According to Google's internal studies, approximately 16% of their tests exhibit some form of flakiness, and Microsoft reports similar numbers. The real damage goes beyond time:

  • Eroded trust: Developers start ignoring test failures, assuming they're "just flaky"
  • Delayed releases: Teams wait for "green builds" that require multiple retry cycles
  • Security blind spots: Genuine failures get dismissed alongside false positives
  • Developer burnout: Constant firefighting of unreliable tests damages morale

    • Traditional approaches—manual quarantine lists, simple retry logic, or brute-force re-runs—treat symptoms rather than causes. AI-powered flaky test elimination analyzes patterns, predicts failures, and identifies root causes at scale. In 2025, this isn't experimental technology; it's a competitive necessity.

    Step 1: Instrument Your Test Suite for Data Collection

    AI models require rich data. Start by enhancing your test execution to capture meaningful signals.

    Create a test execution collector that captures flakiness indicators: 

    flaky_detector/collector.py
    
import time
import psutil
import json
from datetime import datetime
from dataclasses import dataclass, asdict
from typing import Optional
import hashlib

    

    @dataclass
class TestExecutionRecord:
    test_id: str
    test_name: str
    file_path: str
    outcome: str  # passed, failed, skipped, error
    duration_ms: float
    timestamp: str
    commit_sha: str
    branch: str
    cpu_percent: float
    memory_mb: float
    retry_count: int
    error_message: Optional[str] = None
    stack_trace: Optional[str] = None
    
    def to_dict(self):
        return asdict(self)

    

    class TestExecutionCollector:
    def __init__(self, db_connection):
        self.db = db_connection
        self.process = psutil.Process()
    
    def generate_test_id(self, test_name: str, file_path: str) -> str:
        """Create stable identifier for test across runs."""
        content = f"{file_path}::{test_name}"
        return hashlib.sha256(content.encode()).hexdigest()[:16]
    
    def record_execution(self, test_name: str, file_path: str, 
                         outcome: str, duration_ms: float,
                         commit_sha: str, branch: str,
                         retry_count: int = 0,
                         error_message: str = None,
                         stack_trace: str = None):
        
        record = TestExecutionRecord(
            test_id=self.generate_test_id(test_name, file_path),
            test_name=test_name,
            file_path=file_path,
            outcome=outcome,
            duration_ms=duration_ms,
            timestamp=datetime.utcnow().isoformat(),
            commit_sha=commit_sha,
            branch=branch,
            cpu_percent=self.process.cpu_percent(),
            memory_mb=self.process.memory_info().rss / 1024 / 1024,
            retry_count=retry_count,
            error_message=error_message,
            stack_trace=stack_trace
        )
        
        self._store_record(record)
        return record
    
    def _store_record(self, record: TestExecutionRecord):
        query = """
        INSERT INTO test_executions 
        (test_id, test_name, file_path, outcome, duration_ms, 
         timestamp, commit_sha, branch, cpu_percent, memory_mb,
         retry_count, error_message, stack_trace)
        VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
        """
        self.db.execute(query, tuple(record.to_dict().values()))

    Step 2: Build the Flakiness Detection Model

    With data flowing in, create an AI model that identifies flaky tests. Scikit-learn provides excellent baseline models, while LightGBM offers production-grade performance. 

    flaky_detector/model.py
    
import pandas as pd
import numpy as np
from lightgbm import LGBMClassifier
from sklearn.model_selection import cross_val_score
from sklearn.preprocessing import StandardScaler
import joblib

    

    class FlakyTestDetector:
    def __init__(self):
        self.model = LGBMClassifier(
            n_estimators=200,
            learning_rate=0.05,
            num_leaves=31,
            class_weight='balanced',  # Handle imbalanced flaky/stable ratio
            random_state=42
        )
        self.scaler = StandardScaler()
        self.feature_columns = None
    
    def prepare_features(self, df: pd.DataFrame) -> pd.DataFrame:
        """Engineer features that indicate flakiness."""
        features = df.groupby('test_id').agg({
            'outcome': [
                ('pass_rate', lambda x: (x == 'passed').mean()),
                ('fail_rate', lambda x: (x == 'failed').mean()),
                ('total_runs', 'count'),
                ('outcome_variance', lambda x: x.nunique() / len(x))
            ],
            'duration_ms': [
                ('duration_mean', 'mean'),
                ('duration_std', 'std'),
                ('duration_cv', lambda x: x.std() / x.mean() if x.mean() > 0 else 0)
            ],
            'cpu_percent': [('cpu_mean', 'mean'), ('cpu_std', 'std')],
            'memory_mb': [('memory_mean', 'mean'), ('memory_std', 'std')],
            'retry_count': [('avg_retries', 'mean'), ('max_retries', 'max')]
        }).reset_index()
        
        features.columns = ['test_id'] + [col[1] for col in features.columns[1:]]
        
        # Add time-based features
        time_features = self._calculate_time_patterns(df)
        features = features.merge(time_features, on='test_id', how='left')
        
        return features
    
    def _calculate_time_patterns(self, df: pd.DataFrame) -> pd.DataFrame:
        """Detect temporal patterns in failures."""
        df['hour'] = pd.to_datetime(df['timestamp']).dt.hour
        df['day_of_week'] = pd.to_datetime(df['timestamp']).dt.dayofweek
        
        time_agg = df.groupby('test_id').agg({
            'hour': lambda x: x[df.loc[x.index, 'outcome'] == 'failed'].std() 
                    if (df.loc[x.index, 'outcome'] == 'failed').any() else 0,
            'day_of_week': lambda x: x[df.loc[x.index, 'outcome'] == 'failed'].nunique()
        }).reset_index()
        
        time_agg.columns = ['test_id', 'failure_hour_variance', 'failure_day_spread']
        return time_agg
    
    def label_flaky_tests(self, df: pd.DataFrame, threshold: float = 0.1) -> pd.Series:
        """
        Label tests as flaky based on historical behavior.
        A test is flaky if it has inconsistent outcomes (fails sometimes, passes others).
        """
        test_stats = df.groupby('test_id')['outcome'].agg(['mean', 'count', 'std'])
        
        # Flaky = fails between threshold and (1-threshold) of the time
        # AND has been run enough times to be statistically meaningful
        is_flaky = (
            (df.groupby('test_id')['outcome'].apply(
                lambda x: threshold < (x == 'failed').mean() < (1 - threshold)
            )) & 
            (df.groupby('test_id')['outcome'].count() >= 10)
        )
        
        return is_flaky.astype(int)
    
    def train(self, execution_df: pd.DataFrame):
        """Train the flakiness detection model."""
        features = self.prepare_features(execution_df)
        labels = self.label_flaky_tests(execution_df)
        
        # Align features and labels
        features = features.set_index('test_id')
        aligned_labels = labels.reindex(features.index).fillna(0)
        
        self.feature_columns = features.columns.tolist()
        X = self.scaler.fit_transform(features.fillna(0))
        y = aligned_labels.values
        
        # Cross-validate
        scores = cross_val_score(self.model, X, y, cv=5, scoring='f1')
        print(f"Cross-validation F1 scores: {scores.mean():.3f} (+/- {scores.std():.3f})")
        
        self.model.fit(X, y)
        return self
    
    def predict_flakiness(self, test_features: pd.DataFrame) -> pd.DataFrame:
        """Predict flakiness probability for tests."""
        X = self.scaler.transform(test_features[self.feature_columns].fillna(0))
        probabilities = self.model.predict_proba(X)[:, 1]
        
        results = test_features[['test_id']].copy()
        results['flakiness_score'] = probabilities
        results['is_flaky'] = probabilities > 0.5
        
        return results
    
    def save(self, path: str):
        joblib.dump({
            'model': self.model,
            'scaler': self.scaler,
            'feature_columns': self.feature_columns
        }, path)
    
    @classmethod
    def load(cls, path: str):
        data = joblib.load(path)
        detector = cls()
        detector.model = data['model']
        detector.scaler = data['scaler']
        detector.feature_columns = data['feature_columns']
        return detector

    Step 3: Implement Root Cause Analysis with LLMs

    Identifying flaky tests is only half the battle. Use OpenAI API or Anthropic Claude to analyze why tests are flaky: 

    flaky_detector/root_cause_analyzer.py
    
from openai import OpenAI
import json

    

    class FlakyRootCauseAnalyzer:
    def __init__(self, api_key: str):
        self.client = OpenAI(api_key=api_key)
    
    def analyze(self, test_name: str, test_code: str, 
                failure_messages: list[str], execution_stats: dict) -> dict:
        
        prompt = f"""Analyze this potentially flaky test and identify root causes.

    

    TEST NAME: {test_name}

    

    TEST CODE:
    python {test_code} 
    
RECENT FAILURE MESSAGES (from different runs):
{json.dumps(failure_messages[:5], indent=2)}

    

    EXECUTION STATISTICS:

  • Pass rate: {execution_stats['pass_rate']:.1%}
    • 

  • Duration variance (CV): {execution_stats['duration_cv']:.2f}
    • 

  • Average retries needed: {execution_stats['avg_retries']:.1f}
    • 

  • Failure hour variance: {execution_stats.get('failure_hour_variance', 'N/A')}
    • 

    

    Identify:

  • The most likely root cause category (timing, resource contention, external dependency, test isolation, non-deterministic data, race condition)
    • 

  • Specific code patterns causing flakiness
    • 

  • Recommended fix with code example
    • 

  • Confidence level (high/medium/low)
    • 

    

    Respond in JSON format."""

    

            response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            response_format={"type": "json_object"},
            temperature=0.2
        )
        
        return json.loads(response.choices[0].message.content)
